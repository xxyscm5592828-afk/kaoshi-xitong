# DeepTutor 分析与本系统对比（2026-09-21）

> 目的：把港大 HKUDS 开源的 DeepTutor（个人学习助手）与本系统做一次**架构级**对照，只挑「能真正迁移到我们这套单机、离线、应试场景」的想法，其余明确搁置。
> 原则：DeepTutor 与我们是**两种物种**，不是同一条赛道上的竞品。对比的价值不在于「抄功能」，而在于拎出它那套"学情记忆"设计里对我们成立的那部分。
> 本文结论均来自：①DeepTutor 论文 arXiv:2604.26962 与官方仓库 README；②本系统 `kaoshi-xitong/js/` 源码实测。来源见文末。

---

## 1. DeepTutor 是什么（先对齐事实）

| 项 | 事实 |
|---|---|
| 出身 | 香港大学数据智能实验室（HKUDS），2025-12-29 开源，Apache 2.0 |
| 热度 | 39 天破 1 万 Star，111 天破 2 万 Star（官方新闻） |
| 形态 | **服务端 Web 工作区**：Python 3.11+ FastAPI 后端 + Next.js 16 前端，支持 Docker / 多用户账号 |
| 定位 | "Agent-Native Personalized Tutoring"——面向（偏大学/研究型）学习者的**终身**个性化辅导 |
| 技术核心 | 混合个性化引擎（静态知识锚定 SKG + 动态学习者记忆 DPM）+ 闭合辅导环 + 多智能体 |
| 能力面 | 解题、出题、深度研究、可视化、数学动画、交互式书籍、沉浸式阅读/看视频、Co-Writer、Partners（IM 伴侣） |
| 依赖 | 需配 LLM Key（多家）、Embedding、RAG 引擎（LlamaIndex/GraphRAG/LightRAG/PageIndex）、MinerU 解析，跑在服务器上 |

**它的两条主线**（论文自述）：
1. **个性化智能辅导**（有定量评测的部分）：解题 ↔ 出题双向闭合，共享同一份学习者画像。
2. **主动式自主陪伴**（TutorBot/Partners）：把辅导能力做成可自主发起、跨 15 个 IM 渠道的智能体。

---

## 2. 一句话结论

**两者架构几乎正交：DeepTutor 是"云端 + 大模型 + 多智能体 + 通用终身学习"，我们是"单机 + 确定性算法 + 无后端 + 初二应试防抄答案"。**

因此：
- **不要把本系统往 DeepTutor 方向改**（上服务端、账号、多智能体、RAG 引擎会同时击穿我们的隐私、零成本、离线、防抄答案四条护城河）。
- **真正值得偷的是它"学情记忆"的三个设计决策**：①记忆存"推理轨迹"而非"分数"；②记忆有"多分辨率"、可检索、可审计；③"检索到的证据"要进回答，而不是空手问大模型。

## 3. 横向对比（按维度，不按功能堆）

| 维度 | DeepTutor | 本系统 | 谁更贴合我们的用户（初二+家长） |
|---|---|---|---|
| 部署 | 服务端 + Docker + 账号 | **纯前端单机，双击即用** | ✅ 我们 |
| 联网依赖 | 必须联网 + 多家 API Key | **离线优先，无 Key 全量降级** | ✅ 我们 |
| 成本 | 按 token 计费（多智能体更贵） | **零持续成本** | ✅ 我们 |
| 隐私 | 云端、账号、需隔离 | **localStorage 本机，可导出** | ✅ 我们（未成年人场景关键） |
| 学习者建模 | LLM 推断的**多分辨率记忆**（轨迹森林 + 画像 Ds/Dw/Dr） | 确定性**三维掌握度**（正确率×用时×指数遗忘）+ 错题销号 | 平手：我们是"标量+行为闭环"，它是"轨迹+语义记忆" |
| 可复现性 | 依赖模型，非确定性 | **规则引擎，可复现、可单测** | ✅ 我们 |
| 错题闭环 | 记录并用于后续出题（偏"咨询式"） | **D0→D3→D7 强制销号 + 变式 + 顽固回炉** | ✅ 我们（是"作战协议"不是"收藏夹"） |
| 出题 | difficulty-calibrated + 出题-验证两步 | `genVariant` 生成 + `validateQuestion` 入库校验 | 平手：我们缺"难度校准"的显式约束 |
| 答疑 | **引用锚定**（每个事实带可追溯引用） | DeepSeek 直连，**无引用、无本地检索** | ✅ 它（**这是我们最该补的一环**） |
| 应试对齐 | 通用（偏大学/研究），无考纲 | **会考倒计时 / 教学日历 / 学期赛季 / 大考校准** | ✅ 我们 |
| 防抄答案 | 通用问答，可直接给解 | **无搜题，答错先归因再看解析** | ✅ 我们（家长核心焦虑） |
| 主动陪伴 | TutorBot 主动发起、跨渠道 | `scheduler.js` 每日 2 块计划（确定性主动） | 平手：我们是"确定性主动"，更可控 |
| 扩展性 | 技能市场 / MCP / CLI / 插件 | 分层清晰（数据/算法/闭环/AI/UI），无插件市场 | ✅ 我们（够用即可，不需要生态） |
| 评测 | TutorBench + 第一人称"模拟学生"协议 | 265 单测 + 31 条 E2E | 平手：**它的"学生视角评测"思路可借** |

## 4. DeepTutor 值得我们学的（可迁移，共 3 条内核）

### 内核 1：记忆存"轨迹/错因"，不只存"分数"
DeepTutor 的画像 `D = (Ds 会话史, Dw 反复误解清单, Dr 教学反思)`，关键是 **Dw——"有证据支撑的、反复出现的误解清单"**，而非一个会遗忘的分数。
→ 我们现在：`mastery.js` 存标量分，`wrongbook.js` 存每道错题。**缺一个跨错题的"错因聚合层"**（同一类错因反复出现的清单）。这是最便宜、最直接可补的。

### 内核 2：回答要"检索到证据再讲"，不要空手问大模型
DeepTutor 的解题是"先检索（C_rag + C_mem）→ 分步引导 → 带引用成文"。
→ 我们现在：`assistant.js` 直接把题干丢给 DeepSeek。**但我们本地就有 336 个课叶的六段式微课 + 679 道题**——完全可以做一次"本地检索增强"：讲某题前，先把该知识点的本地微课/同知识点题作为上下文喂进去。**0 额外成本、降幻觉、还更贴课本**。

### 内核 3：角色化上下文注入 + "先调查再规划"
DeepTutor 给 planner 注入 `Ds+Dw`、给 writer 注入 `Dr`，且"先调查、后规划、再动笔"。
→ 我们现在：`askWrong / solveSteps / genVariant` 共用一个 `buildWrongContext`。可以显式分角色注入：**提示轮只喂"错因+微课"，解法轮喂"解题步骤"，出题轮喂"错因+历史同类题"**——和我们已有的"先归因再解析"一脉相承，是把现有做法显式化。

## 5. DeepTutor 不适合我们的（明确不做）

| 不采纳 | 原因 |
|---|---|
| 服务端 / 账号 / 多用户隔离 | 击穿"单机、隐私、零运维"定位；未成年人数据不上云是硬约束 |
| 多智能体 / TutorBot 主动 Agent / 15 渠道 IM 伴侣 | 需要长驻服务和持续 token 成本；且"主动推送"对初中生易变成骚扰 |
| RAG 引擎矩阵（GraphRAG/LightRAG/PageIndex）+ MinerU | 我们是固定小规模本地知识库，杀鸡用牛刀；纯前端跑不动 |
| 技能市场 / MCP / CLI 应用 / 插件生态 | 用户是学生和家长，不需要可编程扩展；属过度工程 |
| 云端语义记忆 / 向量检索 | localStorage 5MB 约束下不可行；我们的确定性记忆已足够 |
| 通用问答（会直接给答案） | 与"防抄答案"直接冲突，是家长最痛的点 |

---

## 6. 我们的相对优势（要守住，别被带偏）

DeepTutor 在"通用个性化"上更先进，但**在我们的目标人群上我们更对**：

1. **离线 + 零成本 + 本机隐私**：DeepTutor 越强越依赖 API/服务器，越不适合"给孩子一台电脑长期用"。
2. **确定性可复现**：它的画像靠模型推断，会漂移、会幻觉、不可单测；我们的引擎可写测试、可解释。
3. **行为闭环更强**：它是"咨询式"个性化，我们是"D0→D3→D7 强制销号"，把"针对性练习"变成了不可跳过的流程。
4. **应试对齐**：会考倒计时、教学日历、大考校准是它完全不具备的。
5. **防抄答案**：它天生是通用问答，我们天生不抄——这是卖给家长的核心差异。

> 结论：**站在它肩膀上补"记忆"和"检索"，而不是抄它的"形态"。**

## 7. 优化建议清单

### A 组：学情记忆（最高价值，直接对应内核 1、3）

| # | 建议 | 做法 | 依据（DeepTutor） | 成本 |
|---|---|---|---|---|
| A1 | **错因聚合层** | 从 `wrongbook` 的 `errorType` + `attempts` 聚合出「反复出错的概念清单」（如同一错因在多个知识点反复出现 → 判定为"思维习惯问题"而非"知识点问题"），在报表/家长周报显性化 | Dw：有证据支撑的反复误解清单，而非标量分 | 低（`wrongbook.js`/`report.js` 已有数据） |
| A2 | **本地检索增强答疑**（最强单点） | 提问前按知识点去本地取该课叶的六段式微课 + 同类题，拼进 `assistant.js` 上下文再问模型 | 引用锚定：先检索证据再回答，降幻觉、贴课本 | 中低（`assistant.js` + `lesson.js`，0 额外 API 成本） |
| A3 | **角色化上下文路由** | 把 `buildWrongContext` 拆成"提示轮 / 解法轮 / 出题轮"三份不同的 context，各取所需 | 角色化 profile 注入（planner:Ds+Dw / writer:Dr） | 低（`assistant.js` 单文件） |
| A4 | **「学情记忆」可审计页** | 设置页新增只读视图：展示系统记住了什么（错因清单、掌握度来源、销号记录），支持导出 | 可审计记忆（L1/L2/L3 透明可编辑） | 低（`storage.exportData` 已有） |

### B 组：出题与内容（对应内核 2）

| # | 建议 | 做法 | 依据 | 成本 |
|---|---|---|---|---|
| B1 | **变式题难度校准** | `genVariant` 显式约束"生成题难度 = 原题难度 ±1"，并在 prompt 里带上原题难度与目标区间；入库前继续走 `validateQuestion` | difficulty-calibrated generation | 中（`assistant.js` + `storage.js`） |
| B2 | **微课配轻量示意图** | 给学生高频卡壳的课叶（函数/全等/浮力/凸透镜等）配 1 张纯 SVG 示意图 | 与 DeepTutor 的 Visualize/数学动画同源，也是洋葱完课率的支柱（详见上一份对比 B2） | 中（可分批） |

### C 组：工程与评测（对应"学生视角评测"）

| # | 建议 | 做法 | 依据 | 成本 |
|---|---|---|---|---|
| C1 | **「模拟学生」端到端测试** | 模拟一个"总在同类题出错"的学生，断言：溯源命中根因、D0→D3→D7 走完、答疑首轮只给思路不给答案 | TutorBench 的第一人称"模拟学生"协议 | 中（扩展 `tests/`） |
| C2 | **答疑降级再确认** | 复核无 Key / 429 / 截断时，A2 的"本地检索上下文"是否仍能支撑一个像样的本地回答 | 引用锚定：证据在本地，模型只是表达器 | 低 |

---

## 8. 落地优先级

**第一批（低风险、高感知，建议先做）**：`A1` 错因聚合 + `A3` 角色化上下文 + `A2` 本地检索增强（A2 是本轮最大收益点）。

**第二批**：`A4` 记忆审计页 + `B1` 难度校准 + `C1` 模拟学生测试。

**第三批**：`B2` 微课配图（按知识点分批）。

**明确不做**：服务端化、账号体系、多智能体/TutorBot、IM 多渠道、RAG 引擎矩阵、技能市场/MCP、向量语义记忆、通用问答（防抄答案红线）。
